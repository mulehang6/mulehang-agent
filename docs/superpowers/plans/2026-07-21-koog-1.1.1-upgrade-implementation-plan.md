# Koog 1.1.1 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将项目的稳定版 Koog 依赖从 `1.0.0` 升级到 `1.1.1`，并验证现有 Agent、Provider、工具与 Desktop 代码保持兼容。

**Architecture:** 修改 `shared` 模块的直接 Koog 依赖版本，并在阿里云镜像同步前通过根工程临时直连官方 Maven Central。保留现有显式 Ktor HTTP client factory 和所有运行时接入边界；仅在实际编译或测试失败证明必要时，才对受影响调用点实施最小兼容修复。

**Tech Stack:** Kotlin 2.4.0、Kotlin Multiplatform、Compose Multiplatform 1.11.1、Koog 1.1.1、Ktor 3.3.3、Gradle Wrapper 9.6.1、kotlin.test、JUnit 5。

## Global Constraints

- Koog 目标版本固定为 `1.1.1`。
- 用户级 Gradle init 脚本会重写标准 Central URL；根工程临时使用 `https://repo.maven.apache.org:443/maven2`。
- 不新增 `koog-agents-additions` 或其他依赖。
- 不升级 Kotlin、Compose、Ktor 或其他库。
- 不重构现有 Koog 接入代码，不采用 Koog 1.1.1 新功能。
- 配置升级适用已确认的 TDD 例外：不人为添加失败测试，使用现有测试做升级前后回归。
- 不启动 Desktop 应用、Vite 或任何长期运行服务。
- 保留既有工作区变更；写改文件使用 `functions.apply_patch`。
- 未经用户明确授权不创建提交。

### Task 1: 升级 Koog 并验证兼容性

**Files:**

- Modify: `shared/build.gradle.kts:14`
- Modify: `build.gradle.kts:15`
- Modify only if compilation requires it: Koog 调用点下的受影响 Kotlin 文件
- Verify: `shared/src/commonTest`
- Verify: `shared/src/jvmTest`
- Verify: `desktopApp/src/test`

**Interfaces:**

- Consumes: `ai.koog:koog-agents:1.0.0` 和现有 Koog 接入代码。
- Produces: `ai.koog:koog-agents:1.1.1`，现有项目接口与行为保持不变。

- [x] **Step 1: 运行升级前回归基线**

先读取 IDEA run configurations；已有单项 Koog 配置可用于聚焦检查，但完整模块测试仍使用仓库 Gradle Wrapper：

```powershell
.\gradlew.bat :shared:jvmTest :desktopApp:test
```

Expected: `BUILD SUCCESSFUL`。若基线失败，记录现有失败并在升级后区分，不把既有失败误判为升级回归。

- [x] **Step 2: 修改直接依赖声明并临时切换仓库来源**

在 `shared/build.gradle.kts` 中将：

```kotlin
implementation("ai.koog:koog-agents:1.0.0")
```

替换为：

```kotlin
implementation("ai.koog:koog-agents:1.1.1")
```

不修改其他依赖版本。

由于用户级 Gradle init 脚本会把 `mavenCentral()` 重写到尚未同步 Koog 1.1.1 的阿里云镜像，将根工程仓库临时改为：

```kotlin
maven {
    url = uri("https://repo.maven.apache.org:443/maven2")
}
```

- [x] **Step 3: 检查 Gradle 文件并编译受影响模块**

使用 IDEA `get_file_problems` 检查 `shared/build.gradle.kts`，然后运行：

```powershell

```

Expected: `BUILD SUCCESSFUL`。若失败，只修改错误直接指向的 Koog 调用点，并为每个修改过的 Kotlin 文件运行 IDEA `get_file_problems`；不做预防性迁移。
