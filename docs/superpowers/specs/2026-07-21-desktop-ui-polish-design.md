# Desktop UI Polish Design

## 目标

在不改变聊天、工具调用和权限业务协议的前提下，按 Emil Kowalski 的设计工程原则打磨 Compose Desktop 主界面：高频操作即时、低频信息按需展开、视觉语言统一、窄窗口仍可操作。

## 设计结论

1. 流式输出跟随使用即时滚动，避免每个内容增量重新启动动画；仅显式“回到底部”动作适合动画。
2. Composer 常显附件、Provider、Model、Reasoning、Context 和 Permission；Reasoning 保持独立下拉框。发送/停止使用紧凑图标按钮。
3. 所有可点击壳提供 hover、press、焦点语义和 tooltip。高频键盘发送不添加动画。
4. 用户消息右对齐；Reasoning 与 Tool Event 以摘要行为主，详情按需展开，失败信息保持可见。
5. Plan 在 Composer 上方以单行进度摘要展示，可展开查看步骤；附件允许移除。
6. Copy、Export、Filter 等操作使用不推动内容布局的短时反馈。
7. 空态提供可点击的起步动作，并使用正式产品文案。
8. 颜色、圆角、文字和中英文文案统一到一套语义 token 与中文界面。
9. 小窗口下隐藏右侧工具 rail、收窄侧栏和边距，Composer 控制带允许横向滚动但发送动作始终可见。

## 动效规则

- 按压反馈使用约 `0.97` 缩放和 120ms 左右的快速回弹。
- hover 仅改变背景或颜色，不使用位移动画。
- 高频列表追加、键盘触发和流式滚动不动画。
- 反馈浮层使用 150–200ms 的淡入淡出，不改变主布局。

## 验收标准

- Composer 不再常显独立 Reasoning 选择器，Context Ring 恢复可见。
- 发送/停止按钮显示图形符号，并有可访问说明。
- 用户消息右对齐，工具详情和计划均可折叠。
- 附件可移除；空态动作可直接填充输入草稿。
- 图标动作具备 tooltip 与足够点击区域。
- `:desktopApp:test` 与 `:desktopApp:compileKotlin` 通过，受影响文件无新增 IDEA 问题。

## 下拉框视觉修正

1. 推理强度保持为独立下拉框，不与模型菜单混合。
2. Trigger 使用 `AppChipBackground`，展开时过渡到 `AppSidebarBackground`；popup 同样使用 `AppSidebarBackground`，通过边框和阴影表达浮层关系。
3. Popup 使用 10dp 圆角、`AppLine` 边框、8dp 阴影，并至少与 trigger 等宽。
4. 菜单项高度为 40dp，hover 使用 `AppHoverBackground`，选中项使用 `AppSelectedBackground` 并显示勾选标记。
5. 下拉菜单只使用 120ms 左右的箭头状态反馈，不为键盘操作添加动画。
6. Provider、Model、Reasoning 与 Permission 的说明 tooltip 固定显示在 trigger 下方，避免与受窗口空间影响而向上展开的菜单重叠。
7. 下拉框 tooltip 仅在鼠标连续悬停 `1500ms` 后显示；只要指针仍位于 trigger 上就保持可见，离开时立即关闭。其他按钮和图标 tooltip 保持现有即时反馈，不应用此延迟策略。

## Air 浮动侧栏与工作区分割

1. 主工作区始终占据完整可用宽度；任务侧栏作为覆盖在主工作区左上方的独立浮层，不再参与 `Row` 的宽度分配。
2. 顶部提供侧栏开关。侧栏默认关闭；点击侧栏之外的区域也会关闭。关闭和重开沿同一条水平路径滑动；不改变透明度，不使用渐显或渐隐。
3. 侧栏使用与 Air 参考一致的暗色磨砂玻璃：后方工作区经高斯模糊后极淡透出，前景保持清晰，并使用 12dp 圆角、方向性微光、低对比亮边和柔和深色阴影；不使用液态折射、色散或高频噪点。
4. 位移动画使用无回弹 spring，打开时从左侧窗口外完整滑入，关闭时沿原路径滑出，并允许连续点击时从当前运动状态反向。
5. 主区域与终端是两张独立圆角面板。终端打开时，两者之间出现 8dp 可拖动分隔带；拖动直接更新终端高度，并限制主区和终端的最小高度。
6. 终端关闭时主区域占满可用高度；再次打开时恢复当前会话内上次的高度。窗口缩放时高度重新夹取到合法范围。
7. JediTerm 的 Swing 根组件、终端画布和滚动容器不绘制默认边框，消除终端左侧白线。
8. 右侧 rail 只保留终端入口；历史记录与导出会话后续归入左侧工作区/会话层级。
9. Composer 的下拉框共享单一展开状态；一个菜单打开时点击另一触发器，会直接切换到新菜单。
10. 顶部标题栏只保留左侧菜单按钮和产品名，移除中央的工作区与任务标题，避免重复信息占据视觉中心。
11. Composer 的发送/停止动作使用 40dp 圆角图标按钮：发送状态显示居中的矢量上箭头，停止状态保持清晰的停止符号；按钮保留 tooltip 与约 `0.97` 的快速按压反馈。
12. 下拉框触发器在指针按下时记录自身是否已经展开，并以该快照决定点击结果：点击已展开的触发器直接关闭；点击其他触发器在同一次点击中完成菜单切换，不受旧 popup 的延迟关闭回调影响。
13. JediTerm 挂载到 SwingPanel 后再次清除根容器、终端画布与滚动容器的 Look & Feel 边框，消除嵌入区域左侧的亮色竖线。

## 新增验收标准

- 侧栏开关不会改变主区域的宽度或导致内容横向跳变。
- 侧栏呈现暗色磨砂浮层，后方工作区只能模糊感知位置、不能清晰阅读；不存在液态折射、色散或高频噪点。
- 侧栏切换只发生水平位移，没有渐显、渐隐或原地浮现。
- 终端和主区域分别拥有自己的圆角、背景和边界，中间分隔带可以连续拖动。
- 终端高度始终处于最小值与可用高度约束内，窗口缩放后不会把任一区域压扁到不可用。
- 终端左侧不再出现 Swing 默认白色边线。
- 顶部标题栏不再显示居中的工作区与任务标题。
- 发送按钮使用清晰的矢量图标、稳定的 40dp 点击区域、tooltip 和快速按压反馈。
- 任一 Composer 下拉框均满足：点击自身关闭、点击另一触发器直接切换、点击外部关闭。
- Composer 下拉框 tooltip 在连续悬停 `1500ms` 前不可见，达到延迟后显示在 trigger 下方，并持续到指针离开；展开菜单与 tooltip 不占用 trigger 的同一侧。
