# Koog 1.1.1 升级设计

## 背景

项目当前在 `shared/build.gradle.kts` 中直接依赖 `ai.koog:koog-agents:1.0.0`。Koog 官方最新稳定版本为 `1.1.1`。官方发布说明只列出 Beta 模块的破坏性变更；项目没有直接依赖相关 Beta 模块或使用被移除的 `PromptAugmenter.SECTION_SEPARATOR`。

项目已显式创建 `KtorKoogHttpClient.Factory`，不依赖 Koog 的默认 HTTP client 自动发现，因此本次不需要为了新版 Quickstart 额外引入 `koog-agents-additions`。

当前用户级 Gradle init 脚本会把标准 Maven Central URL 重写到阿里云镜像，而该镜像尚未同步 Koog 1.1.1。升级验证期间，根工程临时使用带显式 `:443` 端口的官方 Maven Central URL，避免被全局规则重写；镜像同步后可恢复为 `mavenCentral()`。

## 目标

1. 将 `ai.koog:koog-agents` 从 `1.0.0` 升级到 `1.1.1`。
2. 保持现有 Agent、流式响应、工具调用、Provider 和 Desktop 行为不变。
3. 通过现有测试、编译与完整构建确认升级兼容性。

## 非目标

1. 不采用 Koog 1.1.1 新增功能。
2. 不新增 `koog-agents-additions` 或其他依赖。
3. 不建立 Gradle version catalog，也不顺带升级 Kotlin、Compose、Ktor 或其他库。
4. 不重构现有 Koog 接入代码。
5. 不修改历史 spec 与 plan 中用于描述当时基线的 Koog `1.0.0` 文本。

## 实施设计

修改 `shared/build.gradle.kts` 中的 Koog 版本号，并在 `build.gradle.kts` 中临时直连官方 Maven Central。升级后先编译并运行现有测试；只有当 Koog 1.1.1 导致实际编译错误或测试失败时，才对受影响调用点做最小兼容修改。

项目继续使用现有的显式 HTTP client factory：

- `KoogHttpClient.Factory`
- `KtorKoogHttpClient.Factory`
- Ktor Java engine

不改变 Provider 路由、Prompt 映射、工具注册或流式事件转换。

## 兼容性判断

Koog 1.1.1 发布说明中的稳定模块改动以新增能力、改进和缺陷修复为主。明确列出的破坏性变更仅发生在 Beta 模块：移除 `PromptAugmenter.SECTION_SEPARATOR`。项目源码没有使用该成员，因此预期无需生产代码迁移。

项目使用到的关键 API 包括 `AIAgent`、`ToolRegistry`、`StreamFrame`、`MultiLLMPromptExecutor`、OpenAI/Anthropic client、Koog HTTP client factory，以及 Prompt/Message 模型。最终兼容性以实际编译和测试结果为准，不仅依赖发布说明推断。

## 测试与验证

本次是依赖配置升级，不新增业务行为，因此不人为构造失败测试。使用现有测试作为回归保障，并执行以下验证：

```powershell
.\gradlew.bat :shared:jvmTest :desktopApp:test --rerun-tasks
.\gradlew.bat :desktopApp:compileKotlin --rerun-tasks
.\gradlew.bat build --rerun-tasks
```

同时检查：

1. `shared/build.gradle.kts` 的 IDEA problems。
2. 若存在兼容修改，检查每个受影响 Kotlin 文件的 IDEA problems。
3. `git diff --check`、任务差异和工作区状态，确保不覆盖既有用户变更。

## 成功标准

1. `shared/build.gradle.kts` 使用 `ai.koog:koog-agents:1.1.1`。
2. 受影响测试全部通过。
3. Desktop 编译与根工程完整构建成功。
4. 除版本升级、临时 Maven Central 覆盖和编译所必需的兼容修改外，没有无关代码或依赖变更。
5. 不启动 Desktop 应用或开发服务器，不创建提交。
