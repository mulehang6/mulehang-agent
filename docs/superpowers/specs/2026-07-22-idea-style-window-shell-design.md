# IDEA 风格桌面窗口外壳设计

## 目标

在不改变聊天、任务侧栏、终端开关、消息发送和窗口生命周期语义的前提下，将 Compose Desktop 界面调整为接近 IntelliJ IDEA 的一体化桌面框架：顶部深色标题区与右侧贴边工具栏形成连续外壳，同时修正截图红字指出的字号、图标尺寸和信息层级问题。

## 范围

- 移除当前白色系统标题栏的视觉分层，优先使用 JBR 原生深色自定义标题栏。
- 保留窗口拖动、最小化、最大化/还原和关闭能力。
- 最大化、还原和最小化使用 Windows/JBR 原生窗口状态过渡，不手动插值窗口尺寸。
- 顶部菜单按钮与“MH Agent”标题作为一个整体，在标题栏内垂直居中。
- 将终端入口调整为 IDEA 风格的右侧贴边工具栏按钮，并扩大按钮和图标。
- 标题栏横跨整个窗口宽度，右侧工具栏从窗口控制按钮下方开始。
- 右侧工具栏使用与顶部标题栏相同的背景色，首个按钮与主工作区顶边对齐。
- 扩大终端面板关闭按钮的点击区和关闭图标。
- 扩大发送按钮中的箭头图标，但保持按钮现有尺寸和行为。
- 调整任务侧栏分组标题、任务卡间距和工作区路径的字体表现。
- 不新增左侧、底部工具栏，不改变现有功能和数据流。

## 方案选择

采用 JBR 1.9.0 提供的 `WindowDecorations.CustomTitleBar`：窗口保留系统装饰能力，但将客户区延伸到标题栏，由 JBR 在客户区上方绘制可配置的原生窗口控制按钮。该 API 与 IDEA 使用的窗口装饰能力同源，能够同时提供统一的按钮几何、原生拖动与双击行为，以及 Windows/JBR 的最大化、还原和最小化过渡。手动窗口边界插值会增加多显示器、任务栏工作区和中断处理风险；内容缩放或淡入不能替代真实窗口过渡，因此不采用。

若运行时不支持 JBR Window Decorations，则回退到现有 Compose 无装饰窗口和自绘窗口按钮，确保窗口仍可操作。回退路径不承诺原生系统过渡。

## 组件设计

### 窗口与标题栏

`Main.kt` 继续负责窗口生命周期。启动时检测 `JBR.isWindowDecorationsSupported()`：支持时使用系统窗口装饰并安装高度值为 48 的 JBR CustomTitleBar；不支持时使用 Compose `WindowDecoration.Undecorated()` 回退方案。JBR/AWT 会处理自身的 HiDPI 变换，因此安装原生标题栏时不再把 48 重复乘以 Compose density；Compose 顶部栏仍使用 48dp。关闭应用语义不变。

`ChatHeader` 保留左侧菜单按钮与产品名，并横跨完整窗口宽度。JBR 路径为右侧原生窗口控制区预留 inset，不再绘制 Compose 字符按钮；JBR 负责拖动、双击最大化、最小化、最大化/还原、关闭和系统过渡。运行时调试证明 JBR 会在 Compose Desktop 的 `SkiaLayer` 收到鼠标事件前完成非客户区命中，因此 Compose `onPointerEvent` 无法修复该按钮。JBR 路径改为只在 36dp 菜单范围内放置与标题栏同色的 Swing/AWT 命中组件，在除 Exit 和 Wheel 外的鼠标事件上调用 `CustomTitleBar.forceHitTest(true)`，并在有效左键释放时触发现有侧栏回调。标题文字和其余空白区域不强制客户端命中，继续保留原生拖动与双击行为。回退路径继续显示现有 Compose 菜单和窗口控制按钮。

### 右侧工具栏

保留现有 `ToolRail` 的终端切换逻辑，只调整其布局和视觉：`ChatScreen` 根布局保持“全宽标题栏 + 下方内容 Row”，工具栏因此严格位于三个原生窗口按钮下方。工具栏贴住窗口右边缘并延伸至内容底部，背景改为与顶部标题栏一致的 `AppHeaderBackground`，保留左侧低对比分隔线。顶部内边距使用 16dp，使首个终端按钮与主工作区 Surface 顶边对齐。终端按钮继续使用约 40dp 点击区域和约 20dp 图标，激活态仍由当前 `terminalVisible` 决定。

### Composer 与终端面板

消息发送按钮保持 40dp 点击区域和现有发送/停止逻辑，仅将箭头绘制尺寸提高到约 18dp，使图标与按钮比例一致。

终端关闭按钮提高到约 36dp 点击区域，关闭符号约 18dp；`onClose` 回调及终端释放流程保持不变。

### 任务侧栏

“进行中”“已完成”等分组标题提高到 13–14sp，降低过度字距。任务卡保留标题、工作区路径和统计信息三层结构，适度增加路径的可读性；工作区路径使用普通 UI 字体风格、单行省略，不呈现类似终端代码的视觉权重。任务选择、搜索和新建逻辑不变。

## 数据流与状态

不新增业务状态。JBR 支持能力、CustomTitleBar 引用和菜单命中回调只属于窗口壳配置；窗口状态继续由 Compose `WindowState` 与原生 Frame 同步。终端激活态仍由 `ChatScreen` 中的 `terminalVisible` 控制；侧栏与 Composer 继续消费现有 `ChatWindowState`。所有改动限定在展示层和窗口壳层。

## 边界与异常处理

- 紧凑布局继续隐藏右侧工具栏，不改变现有阈值。
- 无活动工作区时点击终端，仍显示现有提示，不创建终端。
- 终端启动失败时继续显示现有错误文本。
- JBR 原生按钮直接驱动系统最小化、最大化/还原和关闭；回退按钮根据当前 `WindowPlacement` 切换状态，不引入额外持久化。
- JBR 原生按钮沿用系统可访问性；回退按钮继续提供语义描述和足够点击区域。
- JBR 原生路径直接使用系统窗口过渡，不叠加 Compose spring、缩放或淡入动画。
- 菜单命中覆盖仅在 JBR 原生路径启用，并按 JBR 要求逐个鼠标事件调用；不得把整条标题栏永久标记为客户端区域。
- 原生窗口按钮保留系统 hover/pressed 反馈，但其背景必须完全包含在 48dp 顶部栏内，不得覆盖主内容。
- JBR 不可用时启用自绘回退，避免出现无标题栏且无窗口控制按钮的不可操作状态。

## 验证

- 为可提取的窗口放置状态转换或尺寸规则先补充失败测试，再实现最小改动。
- 使用 IDEA 文件问题检查覆盖所有受影响 Kotlin 文件。
- 运行 `:desktopApp:test` 验证现有交互和状态测试。
- 运行 `:desktopApp:compileKotlin` 验证 Compose Desktop 编译。
- 按截图批注逐项复核：顶部一体化、标题内容居中、右侧终端工具栏、发送箭头、终端关闭按钮、侧栏分组标题及路径字体。
- 覆盖 JBR 支持与不支持两条标题栏配置分支，并验证 JBR 高度不重复乘 density、菜单事件触发客户端命中、右栏背景等于顶部标题栏 token、右栏位于标题栏下方且顶部间距一致。

## 非目标

- 不新增左侧或底部 IDEA 工具窗口栏。
- 不改变终端、聊天、任务创建、搜索或权限选择功能。
- 不实现手动窗口边界动画，不引入新的通用动画或跨平台窗口装饰抽象。
- 不修改 `shared`、React 原型或 vendor 子模块。
