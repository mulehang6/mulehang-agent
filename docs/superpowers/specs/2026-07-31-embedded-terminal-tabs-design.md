# 内嵌终端聚焦与多标签页设计

## 目标

修正右侧终端图标在终端已打开时关闭面板的行为，并让用户可以在同一窗口中保留多个相互独立的 PowerShell 终端页。

## 交互

- 当前工作区已选中且没有终端页时，点击右侧终端图标创建第一个终端页并将焦点移入终端。
- 已存在终端页时，右侧终端图标只尝试将焦点移入当前页的终端；终端已经拥有焦点时不改变应用状态。按钮本身仍保留正常按压反馈。
- 终端标题栏展示可切换的标签页及“+”按钮。“+”创建一个与当前工作区路径绑定的新 PowerShell 终端页，选中并聚焦它。
- 每个标签页都持有独立的终端组件和 PowerShell 进程。切换标签页不会终止后台终端。
- 关闭当前页后，选择相邻的剩余页并聚焦它；关闭最后一页时收起终端面板。
- 标签页在创建时记录工作区路径，后续切换任务不会改变已创建终端的工作目录。

## 结构

在 `chat.component` 中加入可单元测试的终端标签页状态转换：维护标签页列表、当前页和一次性的焦点请求版本。Compose 层根据该状态渲染标签栏，并把焦点请求交给当前 Swing 终端组件执行。

终端组件的创建和生命周期提升至标签页会话：会话创建时启动进程，标签页关闭或窗口销毁时关闭进程。非活动终端保持挂载但不可见，以保证其进程和终端缓冲在标签页切换时持续存在。

焦点处理使用 Swing 当前焦点所有者判断其是否属于当前终端组件；仅在焦点位于终端外部时调用 `requestFocusInWindow`。

## 错误处理

- PowerShell 创建失败时仅在对应标签页展示现有错误文案，不影响其他标签页。
- 没有已选工作区时，保持现有“请先选择工作区”反馈，不创建终端页。

## 测试

状态单元测试覆盖：首次打开、已打开时请求焦点但不关闭、创建并切换第二页、关闭当前页的相邻页选择、关闭最后一页，以及焦点已在终端内时不重复请求。

现有终端样式和滚动条测试继续保留；桌面模块测试与 Kotlin 编译用于集成验证。
