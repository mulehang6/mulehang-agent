# 工具调用分组展示设计

## 目标

将时间线中相邻的成功工具调用合并为轻量、可展开的文本式入口，减少连续工具卡片造成的视觉噪声。保留完整工具参数、输出与失败信息，且不改变 Agent 事件、history 或持久化数据。

## 方案

采用渲染层分组。`ConversationTimeline` 在渲染前把既有 `ConversationItem` 列表转换为展示段；不修改 `ToolEventItem`、`AgentEventReducer`、SQLite 快照模型或 Agent history。

## 分组规则

- 相邻且状态为成功完成的工具事件组成一个组，组的大小允许为 1。
- 遇到聊天消息、思考块、状态事件或失败工具事件时结束当前组。
- 失败工具事件永远单独展示，不会和任何相邻工具合并。
- 组标题固定为 `已执行工具 · N`，默认收起。

## 交互与视觉

- 移除当前工具调用的 Surface 卡片、边框和面板背景。
- 组标题为整行可点击文本入口，悬浮时使用清晰但克制的背景色；标题右侧使用可旋转箭头。
- 展开组后，显示每条工具的无边框文本行：工具名与一行参数摘要。点击文本行展开该工具的完整输出或错误信息。
- 失败工具使用相同的轻量文本行，并保留红色错误文本和展开入口。
- 组与工具行的内容展开/收起使用高度动画 180ms、透明度动画 150ms；箭头旋转 160ms。没有循环、位移或装饰性动画。

## 测试

- 连续成功工具调用合并为一个组，数量正确。
- 聊天消息、思考块和状态事件会打断工具组合并。
- 失败工具独立显示，且不会合入前后的成功工具组。
- 单个成功工具仍以 `已执行工具 · 1` 的统一入口显示。

## 非目标

- 不修改工具事件产生、完成或失败时的领域状态。
- 不迁移数据库，也不改变已保存任务的兼容性。
- 不新增筛选、搜索或工具调用执行控制。
