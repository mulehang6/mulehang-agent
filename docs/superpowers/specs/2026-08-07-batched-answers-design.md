# 批量 Answers 交互设计

## 目标

把 `ask_user` 从单题、立即提交的交互升级为一次收集多题答案的问卷，并将完成后的时间线记录呈现为可展开的 `Answers` 摘要。

## 协议与状态

- `ask_user` 的 Koog 反射参数使用 `questions_json` 承载问题列表；每项包含问题文本和候选项列表。既有单题 `question` 与 `options` 参数继续可用。
- 每项候选项会在共享层规整：去除空白、去重、最多保留 5 项。
- 每题都允许自由输入；提交结果按问题顺序保留问题与最终答案。
- 一个请求只在全部题目有答案时完成，Agent 仅等待并恢复一次。
- 为保持兼容，现有单题 `question` 与 `options` 调用归一为只含一个题目的批量请求。

## 问卷卡

- 卡片按问题纵向排列，候选项一行一个。
- 每题的最后一行是英文自由输入入口，文案使用 `Other…`。
- 点击内置项即选择该项；点击 `Other…` 才展开该题的输入框。
- 所有题目都已选择或填写后，底部显示可用的单一提交按钮；否则保持禁用并给出简洁提示。
- 题卡沿用现有的淡入、上移、轻微缩放入场；卡内题目用不阻塞交互的短间隔渐入。

## 时间线 Answers 摘要

- 不展示 `ask_user` 工具名，也不加入工具调用展示组。
- 完成后仅展示对话图标与 `Answers` 标签。
- 点击摘要后在原位展开，每题显示问题文本及其答案；默认收起。
- 展开和收起使用透明度与内容高度的短过渡，避免内容突变。

## Composer 视觉状态

- 输入区改为参考图二、图三的双层深色表面：外层为圆角描边容器，内层为更深的编辑区域，底部保留独立的控制栏。
- 空闲和等待输入时使用静态蓝色描边；运行中用连续蓝色流光沿外侧描边移动，表达任务仍在执行。
- 流光只使用绘制层的颜色与路径变化，不改变 Composer 的尺寸、内边距或控件布局；停止后立即回到静态描边。

## 边界与验证

- 空题目、空候选项和超过 5 项的候选项必须在协议边界处理。
- 现有单题调用仍可正常完成和展示为一项 Answers。
- 重点测试：候选项上限、批量答案校验、单次恢复 Agent、摘要模型、单题兼容和展开状态。
