# 顶栏反馈与工具时间线动效设计

## 目标

让顶部栏分支交互与参考 Air 尺寸一致，并让工具时间线在运行中清晰说明 Agent 正在做什么。界面应更易扫读、动效更从容，Markdown 高亮不再过亮。

## 范围

- 分支名 hover 背景使用图二的紧凑高度、圆角与水平留白。
- 点击分支后，“已复制”气泡以当前鼠标位置为锚点，并在显示期间随鼠标更新位置。
- 工具组根据当前运行工具展示动作文本；工具、图标和动效按工具语义区分。
- 放大工具组标题、图标和工具行的文字与图标尺寸。
- 放慢工具组与工具详情的展开、收起及组标题切换动效。
- 降低主内容区 Markdown 与行内代码高亮的饱和度和明度。

不改变工具调用、会话持久化或 Markdown 解析的领域行为。

## 顶栏交互

分支 Chip 的点击热区、背景高度、圆角和横向留白对齐图二的视觉比例。原生标题栏与 Compose 回退标题栏共用同一组尺寸常量，避免两个实现出现悬浮尺寸差异。

点击分支时，保留剪贴板写入行为，但全局固定位置反馈改为带坐标的短暂气泡。Compose 标题栏直接记录指针位置；原生标题栏从 Swing 鼠标事件转换为窗口坐标。气泡显示期间由指针移动事件更新锚点；未取得坐标时降级为原有全局反馈位置。

## 工具组状态与文字

工具组的展示状态由该组最新的 `Started` 工具决定。不存在运行工具时，显示既有数量摘要。Shell 工具是例外：Shell 成为当前工具时，不触发动作文本切换，组标题保持当前稳定文本。

| 工具意图 | 名称匹配示例 | 组标题 | 图标与运行态 |
| --- | --- | --- | --- |
| 搜集上下文 | `grep`、目录列举、文件搜索、读取文件 | `Gathering context…` | 放大镜持续横向扫过三行文本；目录使用树节点逐一亮起，读取使用页面扫描线 |
| 编辑 | `edit`、`patch`、`write` | `Editing…` | 笔尖沿文本线缓慢移动，插入光标短促闪烁 |
| Shell | `shell`、`powershell`、`terminal` | 保持稳定标题 | 终端提示符与光标低频脉冲 |
| 其他 | 网络、下载、调用等 | 依据工具名生成简洁英文动作，否则回退数量摘要 | 使用对应语义图标和仅含位移、透明度的循环微动效 |

将“工具名到意图类别”和“意图类别到展示文本/图标/动效”的规则分别做成纯函数。这样新增工具时只需扩展映射，测试也无需依赖 Compose 渲染。

## 过渡和层级

组标题使用双轨内容过渡：旧文本在约 420ms 内向上移动并淡出；新文本从下方进入，在约 420ms 内淡入并上移至基线。图标不跟随文字垂直滑动，使用约 300ms 的淡入与轻微缩放过渡，避免频繁工具切换时产生跳动。

工具组标题、组图标、具体工具行的文字和图标都提高一档，以改善主时间线的扫读性。工具组展开使用约 400ms，收起使用约 300ms；单个工具详情使用相同但更短的节奏。过渡只动画 `transform` 与 `alpha`，并在减少动态效果时保留淡化、移除位移和循环位移动画。

所有 `Started` 工具保持其语义动效；完成、失败、取消后立即定格到对应静态图标。

## 内容高亮

行内代码和 Markdown 强调背景改用低饱和灰蓝色，前景色使用柔和浅灰，不再使用接近白色或高对比蓝色的大片底。链接和明确的交互态仍保留可辨识的强调色，确保信息层级与可访问性。

## 验证

- 单测覆盖分支 Chip 尺寸、指针锚点反馈的降级规则。
- 单测覆盖工具名分类、Shell 例外、活动工具选择、展示文本及动画时长。
- 单测覆盖运行态动画只在 `Started` 生效，以及 Markdown 高亮的目标颜色。
- 每个 Kotlin 文件改动后执行 IDE 问题检查，再运行受影响测试与 `:desktopApp:compileKotlin`。

## 验收标准

1. 分支 hover 背景的尺寸与图二一致，点击反馈出现在鼠标旁并随其移动。
2. 搜索/目录/读取类运行时显示 `Gathering context…`；编辑类显示 `Editing…`；Shell 不切换组标题。
3. 新旧标题按“旧向上离开、新从下方到位”平滑过渡；图标不会垂直跳跃。
4. 所有运行工具均有适合自身意图的动效，结束后静止。
5. 工具组与工具行更易读，展开收起节奏明显更慢，主内容高亮柔和且可读。
